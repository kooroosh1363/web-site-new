# Contributing to Curio

Thank you for helping improve the collection.

## Before opening a pull request

1. Create a focused branch from `main`.
2. Keep each change limited to one clear purpose.
3. Run `npm run check`.
4. Confirm search, filters, bookmarks, the dialog, and both themes still work.
5. Describe what changed and why in the pull request.

## Resource quality

New entries should be useful beyond a single short-lived campaign, link to a reputable source, use concise original descriptions, and include accurate categories and tags. Avoid affiliate links, tracking parameters, duplicates, and promotional copy.

## Code style

- Prefer semantic HTML and browser-native APIs.
- Preserve keyboard access and visible focus states.
- Keep catalog logic pure and covered by tests.
- Do not add a dependency when a small native solution is clear and maintainable.
